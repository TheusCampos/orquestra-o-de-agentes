# website
Perfil: website

Pedido: Crie um site de portfólio responsivo com navegação por teclado e formulário com validação local.

Aceitação: Fluxo completo, estados visíveis, build quando aplicável e indicação clara de envio simulado. Antes de implementar, registrar público, direção visual, composição, tipografia, paleta e contrato de animação. Quando motion fizer parte do briefing, demonstrar entrada, microinterações e comportamento reduzido; não aceitar só declaração CSS como evidência de execução.

Inspecionar página em navegador nos tamanhos desktop e mobile, sem overflow horizontal; percorrer menu, CTA, formulário, foco e Escape. Salvar screenshots e comparar hierarquia, legibilidade, identidade e acabamento com o briefing. Registrar pelo menos uma rodada de correção quando houver defeitos. Sem navegador, marcar validação visual pendente.

Para avaliar colaboração, registrar IDs runtime, mensagem de contrato entre frontend e QA/reviewer, ACK, decisão e revisão integrada. Para avaliar memória, registrar checkpoint no projeto do site e recuperá-lo por Read em uma retomada independente; não confundir memória da biblioteca com a do site.

Executar em projeto descartável representativo. Registrar comandos, arquivos, resultado e limitações. Não usar produção.
